# 見送りと Prunlet の打ち切り

次の target は、その回は触りません。

- P が1つも無い（cargo の registry・git キャッシュなど、署名入りの `CACHEDIR.TAG` だけを持つ）。走査も R4 もせず、ログに「P なし」と残します。
- ごみ箱が有効、または判定できない。
- cargo が使用中（P ごとの `.cargo-lock`・`.cargo-build-lock`・`.cargo-artifact-lock` を排他ロックで取れない）。ロックは target ごとに全 P 分を取り、走査し直し・計画・削除が終わるまで持ちます。ロックのファイルは作りません。
- 走査で読めない項目がある（先頭10件をログへ）。
- 直近2時間以内に更新されたファイルがある。

## Prunlet の打ち切り

Prunlet の1回の呼び出しは10分（`prunlet_timeout_secs`）で打ち切り、結果不明（`ambiguous`）として数え、再送しません。出力を読めない場合など、削除されたか分からないときも同じです。1件でも `ambiguous` が出たら、ロックを解放して実行全体を止めます（残りの target は処理せず、終了コード 3）。

打ち切ったときは、削除の途中で build の一部だけが残っていることがあります。cargo は次のビルドで足りない分を作り直すだけなので、手当ては要りません。
