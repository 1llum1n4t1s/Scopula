# R3: ユニットの使用中判定

cargo の新配置 `P\build\<pkg>\<hash>` のユニットは、lib・ビルドスクリプト・その実行・features や host/target の違いごとに別で、名前から世代の新旧を決められない。cargo は最新のユニットを書き直さないため、更新日時だけでも使用中か分からない。

## 方法（`plan/graph.rs`）

1. P の最終ビルドから `seed_days` 以内のユニットを起点にする。
2. 各ユニットの `fingerprint\<16桁>.json` の `deps` を推移的にたどり、届くものを使用中にする。
3. 使用中でなく、指紋もファイルも `unit_days` 以上古いものだけを R3 の候補にする。

## 判断

- triple の P は host の P のユニット（ビルドスクリプト・proc-macro）に依存するので、P をまたいで索引化する。
- `deps` は u64 をリトルエンディアンの16進にしたものが依存先になる。
- 0 バイトの指紋ファイルは cargo がビルド前に空にしたまま残ったものとして、指紋値なしとして扱う（JSON の `deps` は読む）。それ以外の読めない指紋・JSON は壊れ扱いで、その target の R1・R3・R6 を止める。
- R6 は、R6 の対象にならない P の起点から届くユニットを持つ P を外す（`profiles_in_use`）。`--target` だけでのビルドで host 側の P が古くなる場合を守る。
